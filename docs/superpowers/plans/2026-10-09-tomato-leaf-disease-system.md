# Tomato Leaf Disease Classification System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a reproducible PyTorch tomato leaf disease classifier with SimpleCNN and ResNet18 experiments, independent evaluation, Grad-CAM explanations, and a Chinese Streamlit demonstration UI.

**Architecture:** Keep data preparation, dataset loading, model construction, training, evaluation, inference, explanation, and UI as separate Python modules with explicit interfaces. Training writes self-describing checkpoints and immutable run artifacts; evaluation and Streamlit consume those artifacts without retraining.

**Tech Stack:** Python 3.11, PyTorch 2.6+, torchvision 0.21+, scikit-learn, pandas, NumPy, Pillow, Matplotlib, Seaborn, Streamlit, pytest.

**Spec:** `docs/superpowers/specs/2026-10-09-tomato-leaf-disease-system-design.md`

## Global Constraints

- Work only in `D:\人工智能\番茄叶片病害识别系统`; do not modify `D:\人工智能\4图像分类系统`.
- Use the unaugmented PlantVillage source and only labels whose stable identifier begins with `Tomato___`.
- Preserve the ten English PlantVillage label identifiers in a fixed tuple; keep Chinese display text in separate metadata.
- Use seed `42`, image size `224×224`, and stratified split ratios `0.70/0.15/0.15`.
- Default to batch size `32`, `num_workers=0` on Windows, SimpleCNN `20` epochs, ResNet18 head `5` epochs plus layer4 fine-tuning `15` epochs, early-stopping patience `5`, weight decay `1e-4`, initial learning rate `1e-3`, and fine-tuning learning rate `1e-4`.
- Detect content duplicates before splitting and never place one content hash in more than one split.
- Apply random augmentation only to the training split; validation, test, and inference transforms are deterministic.
- Select checkpoints using validation Macro-F1; use the test split only in the final evaluation command.
- Every checkpoint must contain weights, model name, class order, preprocessing metadata, training configuration, best epoch, and best validation metrics.
- Automatically run on CPU when CUDA is unavailable; never silently change a recorded batch size after an out-of-memory error.
- Do not commit datasets, virtual environments, checkpoints, run logs, or generated report images.
- The UI may describe model output but must not provide pesticide dosage, treatment prescriptions, or professional guarantees.
- Report only metrics generated by the implemented evaluator; never add assumed accuracy values to documentation.

## Review Focus

- Duplicate bytes under different filenames: data preparation must keep every matching SHA-256 hash in exactly one split; Task 2 pins this behavior.
- Corrupt or unreadable image: preparation must fail with the offending relative path instead of silently reducing the dataset; Task 2 pins this behavior.
- Checkpoint model or class-order mismatch: inference and evaluation must reject it before loading weights; Task 5 pins this behavior.
- Grayscale and transparent PNG input: inference must convert both to RGB and preserve a valid `224×224` tensor; Task 8 pins this behavior.
- Non-image upload or low-confidence result: the UI must show a Chinese validation/warning message without a Python traceback; Task 9 pins this behavior.

- `train.py`: training/evaluation epochs, early stopping, run directory creation, and CLI.
- `evaluate.py`: test-only metrics, confusion matrices, error cases, and efficiency comparison.
- `predict.py`: inference bundle loading, RGB conversion, Top-3 result, and timing.
- `explain.py`: ResNet18 Grad-CAM generation and overlay.
- `app.py`: Chinese Streamlit pages consuming saved artifacts.
- `tests/`: unit and integration tests mirroring the owning module.
- `README.md`, `requirements.txt`, `.gitignore`: environment, workflow, and repository hygiene.
